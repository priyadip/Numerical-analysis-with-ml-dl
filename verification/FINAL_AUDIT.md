## What is deliberately not claimed

- **This is the final audit.** All 98 lessons are written and all 514 tracked
  concepts are covered, so the two numbers this section used to hedge about are now zero and
  100.0 per cent.
- **Complete does not mean exhaustive.** The concept list is the one built from the three supplied
  sources plus the supplementary topics named in the per-part audits, and it is complete against
  that list and against nothing wider. Section G of each part-level audit says what that part
  deliberately leaves out.
- **"Source chapters fully absorbed" means**: of the 81 (source, chapter) groups in
  the checklist, 81 have every one of their tracked concepts covered. The
  definition changed once, at Part 5, and is not comparable with revisions of this file before
  that; the earlier figure counted only groups holding three or more concepts. The definition is
  stated here so it can be checked, which the old one was not.
- **The Trefethen and Bau material is now completely covered**: all 75 tracked concepts, the
  last three of them in lesson 65. Trefethen carries the greatest depth of any source in Parts 3
  to 6, as intended. **Parts 10 and 11 attribute nothing to Trefethen and Bau**, because the book
  covers numerical linear algebra and has no material on differential equations. Where they need
  linear algebra they cite the earlier parts that took it from Trefethen and Bau, and lesson 79's
  non-normality and pseudospectra are the largest such debt.
- **Sauer chapters 6, 7 and 8 and Gupta chapters 14, 15 and 16 are now complete**, which is the
  whole of the differential equation material in the sources, ordinary and partial.
- **The generality scan covers 488 files: every library module, test, notebook, built lesson and worked solution.** Earlier revisions of this file quoted a file count from
  a list that is not the current one, so the counts are not comparable across revisions; the
  current definition is the standalone scanner's, stated in
  [`check_generality.py`](../_planning/check_generality.py).
- **"Words across all markdown lessons" counts code blocks as well as prose.** At 98 lessons
  that is 410196 words, of which 237304 are outside the fenced code.
- **The coverage flags were wrong until Part 9 and are now right.** `tested` was decided by a
  table that stopped at lesson 08, and `experimented` required an inline figure, which no lesson
  in Parts 7, 8 or 9 produces. Both are now read off the lesson itself, and
  [AUDIT_PART9.md](AUDIT_PART9.md) section D records it. **Only the `covered` count was ever
  quoted in this document, and it was unaffected.**
- Timing measurements anywhere in the course are machine specific. Where a lesson depends on
  one, it checks the *mechanism* rather than asserting a particular number.

## How to reproduce every number here

```bash
pip install -r requirements.txt
python verification/run_all.py
```

Nine checks: rebuild and execute every notebook, run the test suite, recompute the identity
checks independently, regenerate the coverage checklist from what actually exists, check that
every notebook has a matching markdown lesson, resolve every relative link in every markdown
file, sweep the whole repository for placeholders, scan every source file, notebook, markdown
lesson and solution for hardcoded dimensions, and sweep every text file for the control
characters a mangled shell escape leaves behind. It writes every generated report in this
directory and exits non-zero if anything fails.
